## Reflective Journal Final Project 1

*November 12-19, 2026*

Did some experimentation and decided to try using the q5play framework, which has led to a lot of different wins and challenges. Pippin was definitely correct in that it's possible to spend all my time learning the new tool/engine instead of working on the project, which I have encountered numerous times. The main thing that made me really want to try and learn q5play despite it being so new was a cool demo of the particle effects which was easily able to render many thousands of sprites smoothly in browser.

After spending a couple of days playing around with q5, I really like the feel and aesthetics of the projects it produces, so I decided to forge ahead with it. Although this has definitely been challenging (I think the framework is really new and not that popular, there are no YouTube tutorials that I could find) the engine seems awesome and has allowed me to do a lot of fun stuff with my project.

For the final project I wanted to create a digital version of my CART 214 final project, which is an interactive card deck/toy called "Elevator Pitch". The idea of the physical version is to arrange/play with cards to create "elevator pitches" for new video games, often in the format "It's like Game X meets Game Y". It's meant to spark ideas, conversations, coding challenges, or as a game with friends. The core idea of the project is to be playful, which I really want to drive home in the digital version. 

For the digital edition I am working on creating a much more playful and unrealistic version, including lots of different physics based 'toys' and 'tools' to play with. 

I have lots of ideas that I hope to implement, and am really happy with my progress so far, even though I have spent a lot of time with challenges that seem like they should have been relatively simple (it was actually relatively complicated to draw the game cards as rhombuses instead of sqaure/rectangular, because the q5play sprite engine defaults to rectangles and cirlces, but this was important for the "memphis" 80's aesthetic that I am going for.) One thing I was not able to implement was using a custom font on the sprites, which feels like it is a current limitation of the engine (likewise with offseting the text position on sprites).

I am really enjoying refactoring the code as I go along, and trying to make my code more readable and clean. I know that this is something I can keep improving and this project has been giving me lots and lots of practice. I'm glad we will still have a few more weeks to keep playing/experimenting and adding fun features and polish.
