## Reflective Journal

*September 16, 2026*

I studied programming at a couple of different points in my life, the first time that I formally studied it, I don't recall version control or git being a major topic (this was roughly 15 years ago.) The second time I tried to learn more formally was during the pandemic, I had joined a programming boot camp style program which was unfortunately interrupted early on by the lockdowns, and I did not end up continuing with the program at that time. We definitely discussed the importance of version control and started using git on a command line, but I recall never really understanding the concepts of branches and merges and getting confused and frustrated. This time, using the desktop GUI and only doing commit and push commands, hopefully I can build up more familiarity piece by piece instead of getting overwhelmed with too many concepts at once. Git still makes me somewhat uncomfortable, but I think thats because I am associating it with the frustration and confusion I experienced in the past.

I am more familiar and comfortable with markdown, as it was used in a messaging app at a previous company I worked with, I would often post morning messages using headers, emojis, checklists, etc... we made frequent use of the code block feature, because we were doing language quality assurance it was a good way to clearly deliniate a line of text to be corrected
```
which would look like this
```
I recall always having to explain to new team members that the symbol for the code block was not a single apostrophe, rather the accent mark located above the tab key, I'm still not exactly sure what the name for this symbol is. 

I really like the simplicity of markdown, and I often find myself putting an *asterisk* around text to italicize, even in text messages to friends etc... (I know facebook messenger will italicize text this way, but I believe signal just displays the asterisk's) I look forward to hopefully learning some more cool markdown tricks throughout the semester!
