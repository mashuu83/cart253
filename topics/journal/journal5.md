For my first sketch this week, I wanted to have the program ask the user to hold down a random key, this was a fun puzzle to implement. I used random() to get a number in the range of the ASCII letters, then used a function built into the String class in order to convert that into a string of the character. One problem I ran into was that the function I needed to use started with a capital letter, which confused me. Pippin gave a good explanation, but I'm looking forward to understanding object principles better over the upcoming semesters and having a better grasp on this...

The behavior will keep asking for new keys as long as you keep holding them down, but resets when any key is released. Basically, it can never be satisfied, which is a fun interaction (well, fun for a certain kind of person.) Also used the timeout() function a couple of times with this sketch, which I really enjoy adjusting to change the 'feeling'. Just realized in testing that I think the timeout will call multiple times if you release multiple keys, so the 'farther' you progress, the longer the reset time will be, which is an interesting outcome.

For Sketch 2, I wanted to combine an exploration of typography for CART 214, where this weeks assignment is to take an existing project and explore different implementations of typography. While I was browsing the p5 reference I saw a funciton called textToModel() which sounded like it would be really fun to play with (and it is!)

When I implemented the 3D text and only render the background in setup(), I really liked the effect of the trails of text you could create by manipulating the camera controls. Adding visible controls (buttons) to change the font would end up being the most time-consuming aspect of this sketch. I tried some solutions where I created another UI Buffer to render alongside the 3D image, but the camera orbit controls will also affect this element no matter the order in which they are drawn or layered, so I ended up with a much simple (albeit uglier) implementation directly in HTML. This allowed me to explore events triggered from the HTML file and not the js directly.

There is a ton of re-used code in the current implementation of this sketch, so as I get more comfortable with using parameters with funcitons, I would like to refactor and clean up this project, which would also give me a chance to add some more functionality like allowing the user to edit things like size, color, and extrusiton.
Another testing realization is that the scale() function will change the size of the model depending on the size of the string, which has a cool outcome of making very short strings quite large, an cool way to let the user adjust the size without needing to add any new code/functionality.
